# 扫码收货

采购到货时，仓库人员在手机 / PDA 上选择采购订单，逐个扫描物料条码累计收货数量，确认后直接生成采购入库单并入库，与在后台「供应链 → 采购 → [采购入库](../scm/purchase-in)」中办理的效果相同。

## 页面入口

移动作业首页 → 扫码收货（需要采购入库新增权限）

## 第一步：选择采购订单

![选择采购订单](/images/manual/mobile/receive-orders.jpg)

- 页面列出「已审核」「部分完成」状态的采购订单（最近 50 张），显示订单号、状态、供应商、订单日期；
- 在扫码框中扫描或输入采购订单号后回车，按单号查找；只找到一张时自动进入；
- 点击订单卡片进入收货。订单没有待入库的明细时提示「订单没有待入库的明细」。

## 第二步：扫码收货

![扫码收货](/images/manual/mobile/receive-scan.jpg)

页面上方显示订单号、供应商和「换订单」链接，以及**收货仓库**（默认带出订单的仓库，可更换）。下方每张卡片是一行待入库明细，右上角显示「本次收货 / 待入库数量」，收满后变为完成色。

每行可填写：

| 字段 | 说明 |
| --- | --- |
| 数量 | 本次收货数量，不超过待入库数量（订单数量 − 已完成数量 + 退货补发数量）；序列号物料由扫描的序列号个数决定，不能手改。手机收货不支持超收，即使[业务参数](../system/biz-rule)中设置了采购入库超收比例，超收也需要在后台[采购入库](../scm/purchase-in#超收)中办理 |
| 库位 | 收货库位，空着时确认入库会按[上架策略](../wms/label-putaway#上架策略)自动推荐 |
| 批次 | 仅批次物料，必填 |
| 序列号 | 仅序列号物料，选中该行后扫描序列号，标签可点 × 删除 |

### 扫码规则

| 扫描内容 | 效果 |
| --- | --- |
| 库位标签 | 设为「当前库位」（显示在扫码框下方，可「清除」）；当前选中行还没有库位时填入该库位。之后扫描的物料自动使用当前库位 |
| 物料条码 / 编码 | 找到订单中该物料的行（优先未收满的行）并选中：普通物料数量 +1（包装条码按换算率增加，如「+20 个（1 箱）」）；序列号物料提示「请扫描序列号」。物料不在订单中提示「不在该订单中」，超过待入库数量提示「已超过待入库数量」 |
| 其他条码 | 作为当前选中的序列号物料的序列号：重复扫描提示「已扫描」，个数不能超过待入库数量 |

### 确认入库

底部显示「本次收货」合计，点「**确认入库**」：

1. 检查已选择收货仓库、批次物料已填写批次号；
2. 没有库位的行按上架策略推荐库位；
3. 生成采购入库单（业务日期为当天），保存即入库，提示「已入库」并回到订单列表。

## 操作步骤

1. 打开「扫码收货」，扫描采购订单号（或点击订单）；
2. 确认收货仓库；
3. 扫描库位标签设定收货库位（可选，例如收货暂存区）；
4. 逐个扫描物料条码，序列号物料扫描后再逐个扫描序列号；批次物料填写批次号；
5. 核对各行数量，点「确认入库」。

## 与其他模块的联动

- 生成的采购入库单与后台办理的完全相同：回写[采购订单](../scm/purchase)的已入库数量、生成[应付](../fin/ar-ap)等后续业务；
- 物料需要[来料检验](../qms/inspection)的，入库后冻结为待检，见[库存冻结](../wms/hold)；
- 收到暂存区的货物可用[上架](./putaway)移到存储库位。

::: warning 注意
采购入库保存即生效，不能修改删除；收错时需要在后台办理[采购退货](../scm/purchase-in#新增采购退货)。
:::
