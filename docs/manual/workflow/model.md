# 流程模型

流程模型是审批流程的定义：包括基本信息（名称、标识、分类）、表单（申请人要填写的字段）和流程（经过哪些审批人、条件和抄送）。管理员在这里新建流程、设计表单与流程、发布版本、启用或停用。

## 页面入口

流程中心 → 流程管理 → 流程模型

![流程模型](/images/manual/workflow/model.jpg)

## 查询条件

| 条件 | 说明 |
| --- | --- |
| 名称 | 按流程名称模糊查询 |
| 分类 | 按流程分类筛选 |

## 列表字段

| 列 | 说明 |
| --- | --- |
| 流程 | 图标、流程名称和流程标识。由业务单据提交审批的流程带蓝色「业务单据」标签，鼠标悬停显示「由「业务名称」业务单据提交审批」 |
| 分类 | 采购、销售、库存、财务、人事、生产、项目、行政、质量、其他等 |
| 版本 | 已发布的显示当前版本号（如「v1」），未发布显示「未发布」；还没有设计时另显示橙色「未设计」 |
| 状态 | 启用 / 停用开关，需要「模型修改」权限 |
| 排序 | 「发起申请」页面中的显示顺序，数字小的在前 |
| 发布时间 | 最近一次发布的时间 |
| 更新时间 | 最近一次修改的时间 |

## 按钮

| 按钮 | 作用 | 权限 |
| --- | --- | --- |
| 「新增流程」 | 新建流程模型的基本信息 | 模型新增 |
| 「批量删除」 | 删除勾选的流程模型 | 模型删除 |
| 「设计」 | 打开全屏设计器，设计表单和流程 | 模型修改或模型发布 |
| 「编辑」 | 修改基本信息 | 模型修改 |
| 「更多」→「发布」 | 把当前设计发布为新版本；未设计的流程不可发布 | 模型发布 |
| 「更多」→「删除」 | 删除该流程模型 | 模型删除 |
| 工具栏 | 导出列表、显示 / 隐藏查询条件、刷新、调整行高、设置显示的列 | — |

## 新增 / 编辑流程

![新增流程](/images/manual/workflow/model-form.jpg)

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 流程名称 | 是 | 最多 64 个字符，如「采购申请」 |
| 流程标识 | 是 | 流程的唯一编码，以字母开头，只能包含字母、数字、下划线，最多 64 位，如「leave」。不能与其他流程重复，**发布后不能修改**。业务单据的流程必须使用规定的标识（见[业务单据审批](./business)） |
| 分类 | 否 | 「发起申请」页面按分类分组 |
| 图标 | 否 | 从图标库中选择，显示在流程卡片上；不选时使用默认审批图标 |
| 排序 | 否 | 默认 0 |
| 说明 | 否 | 最多 255 个字符，展示在「发起申请」页面的流程卡片上 |

新建的流程默认为启用状态，但还需要设计并发布后才能使用。

## 设计流程

点「设计」打开全屏设计器，分为「表单设计」和「流程设计」两个页签（默认显示流程设计）：

- **表单设计**：定义申请人在「发起申请」中填写的字段，详见[流程设计器 - 表单设计](./designer#表单设计)。
- **流程设计**：仿钉钉的可视化设计器，配置审批人、抄送人、条件分支、并行分支，详见[流程设计器](./designer)。

![流程设计器](/images/manual/workflow/designer.jpg)

设计器顶部：

| 元素 | 说明 |
| --- | --- |
| 返回箭头 | 关闭设计器。有未保存的修改时提示「放弃未保存的修改？」，可选「放弃修改」或「继续编辑」 |
| 状态标签 | 「已发布 v版本号」或「未发布」；有修改未保存时显示橙色「有未保存的修改」 |
| 「保存」 | 校验并保存设计草稿，不影响已发布的版本。需要「模型修改」权限 |
| 「保存并发布」 | 校验、保存并立即发布新版本，提示「发布成功，当前版本 vN」。需要「模型发布」权限 |

保存时如果设计不完整，顶部显示红色提示「请修正以下问题后再保存」并列出全部问题，有问题的节点在设计图上标红，自动切换到出错的页签。

## 发布与版本

- 每次发布都会生成一个**新版本**（v1、v2……）。发布确认框提示：「发布后生成新版本，新发起的申请使用新版本，进行中的申请仍按原版本执行。」
- 已发起的流程始终按发起时的版本流转，流程详情中的表单和流程图也按该版本显示，因此修改设计不会影响审批中的申请。
- 「保存」只保存草稿，草稿要「发布」后才对新申请生效。

## 启用与停用

- 停用的流程不再出现在「发起申请」中，已发起的流程不受影响，继续审批。
- 对于业务单据的流程，停用（或未发布、已删除）后，对应的业务单据不再提交审批，操作直接生效，详见[业务单据审批](./business)。

## 删除

删除确认框提示：「删除后不能再发起该流程，已发起的申请不受影响。」已发布的版本和历史记录保留，审批中的流程继续运行，流程详情仍可查看。

## 内置流程

系统初始化时内置了一批流程模型，可以直接调整审批人后使用：

- **通用流程**（可在「发起申请」中发起，带表单）：出差申请（出差 ≥ 5 天或费用 ≥ 1 万元时上级主管审批）、用印申请（公章、合同专用章需总经理审批）、物品领用（抄送仓库）、通用审批（部门主管 → 上级主管）。
- **业务单据流程**：采购订单、销售订单、补料申请、请假加班、招聘需求、人事异动、工资表、凭证、付款、项目立项、项目费用、请购单、销售报价、盘点差异、费用报销、员工借款、销售合同、订单变更、出入库、不合格品处置、采购合同、工程变更等，每个模型的「说明」中写明了内置的审批链，完整清单见[业务单据审批](./business)。

::: tip 提示
内置流程中审批人多为「部门主管」或「指定角色」（总经理、会计、人事专员等）。使用前请在「[部门管理](../system/dept)」中设置部门负责人，在「[用户管理](../system/user#分配角色)」中给相关人员分配角色，否则审批人为空时会按节点设置自动通过或转交超级管理员。
:::
