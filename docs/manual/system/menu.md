# 菜单管理

菜单管理维护系统的导航结构和权限点：顶部导航的模块、侧边栏分组、页面菜单，以及页面上的按钮权限。角色授权时勾选的就是这里的菜单树。

::: warning 平台专属
菜单管理是平台专属功能，SaaS 模式下只有平台租户的管理员可以使用，修改对所有租户生效。日常运维一般不需要改动菜单，新增页面通常随系统升级一起提供。
:::

## 页面入口

系统管理 → 菜单管理

![菜单管理](/images/manual/system/menu.jpg)

## 菜单的三种类型

| 类型 | 用途 | 示例 |
| --- | --- | --- |
| 目录 | 一级目录是**模块**，与「首页」一起显示在顶部导航栏；模块下的二级目录是侧边栏中的**分组** | 「供应链管理」（模块）→「采购」（分组） |
| 菜单 | 对应一个页面，显示在侧边栏中 | 「采购订单」 |
| 按钮 | 只有权限标识，不显示在导航中，用于控制页面上的操作按钮 | 「订单新增」「订单审核」 |

页面地址由上级目录的路由地址拼接而成，例如模块路由 `/scm` 下的菜单 `purchase`，页面地址为 `/scm/purchase`；二级分组目录不填路由地址，不参与拼接。

## 查询与列表

| 查询条件 | 说明 |
| --- | --- |
| 菜单名称 | 模糊匹配，命中的菜单会连同上级一起显示并自动展开，名称中的关键字高亮 |
| 状态 | 启用 / 停用 |

列表为树形表格，列为：菜单名称（含图标）、类型、路由地址、组件路径、权限标识（可点击复制）、排序、状态（停用或隐藏时会额外显示「隐藏」标签）、操作。

工具栏：「新增菜单」新增顶级菜单；「展开全部 / 折叠全部」。

行内操作：

- **新增**（目录、菜单行才有）：在当前行下新增，目录下默认新增「菜单」，菜单下默认新增「按钮」，排在最后；
- **编辑**；
- **删除**：有子菜单时按钮不可用，必须先删除子菜单。

## 新增 / 编辑菜单

![新增菜单](/images/manual/system/menu-add.jpg)

| 字段 | 适用类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 上级菜单 | 全部 | 是 | 「顶级菜单」或某个目录 / 菜单（按钮不能作为上级）；编辑时不能选自己及下级 |
| 菜单类型 | 全部 | 是 | 目录 / 菜单 / 按钮，默认「目录」 |
| 菜单名称 | 全部 | 是 | 显示在导航、标签页和角色授权树中 |
| 排序 | 全部 | 否 | 数字越小越靠前 |
| 图标 | 目录、菜单 | 否 | 从图标选择器中选择，显示在导航和侧边栏中 |
| 路由地址 | 目录、菜单 | 菜单和一级目录必填 | 一级目录以 `/` 开头（如 `/system`）；二级目录作为侧边栏分组，可不填；菜单写相对路径（如 `user`），会拼接在上级目录之后 |
| 组件路径 | 菜单 | 是 | 页面文件的位置，如 `system/user/index`，由开发人员提供 |
| 权限标识 | 菜单、按钮 | 否 | 如 `sys:user:list`、`sys:user:add`。菜单的权限标识控制能否查看页面，按钮的权限标识控制具体操作，必须与系统中使用的标识一致 |
| 是否显示 | 目录、菜单 | 否 | 「隐藏」的菜单不显示在导航中，但有权限的用户仍可通过地址访问 |
| 状态 | 全部 | 否 | 「停用」的菜单及其权限对所有用户失效 |

保存后提示「保存成功，刷新页面后左侧菜单生效」。

## 操作步骤

**调整模块或菜单的顺序**：编辑对应菜单，修改「排序」，保存后刷新页面。

**临时下线某个页面**：编辑该菜单，把「状态」改为「停用」。

**新页面上线**（开发人员提供页面后）：

1. 在对应的模块或分组下点「新增」，类型选「菜单」，填写名称、路由地址、组件路径、权限标识和图标。
2. 在该菜单下继续「新增」按钮权限。
3. 到[角色管理](./role)为需要的角色勾选新菜单和按钮。

## 注意事项

::: tip 提示
- 菜单名称、图标、排序这类修改只影响显示；修改权限标识、组件路径、路由地址会影响功能，请与开发人员确认后再改。
- 菜单变更后权限缓存会自动清理，用户刷新页面即可生效。
- 多语言：本页列表和表单中是保存的菜单名称（中文）。系统内置菜单已带英文译文，英文界面下导航、侧边栏和标签栏显示内置的英文名称（即使在这里修改了中文名称）；自己新增的菜单没有译文，英文界面也显示这里填写的名称。见[语言切换](../guide/layout#语言切换)。
:::
