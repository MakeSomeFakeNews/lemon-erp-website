# 业务参数

业务参数集中管理各业务模块的控制规则，例如采购入库能否超收、销售出库能否超发、客户信用额度在哪些环节控制、制单人能否审核自己的凭证，以及工资计算用的月计薪天数、每日工时、默认社保比例、考勤的午休扣除、加班倍数、个税预扣率表等人事计算规则。企业可以按自己的管理要求调整，不需要修改系统。

## 与「参数设置」的区别

| | 业务参数（本页） | [参数设置](./config) |
| --- | --- | --- |
| 管什么 | 业务规则：超收超发、信用控制、凭证审核、薪资考勤计算规则等 | 系统级设置：系统名称、登录验证码、密码策略、会话、附件大小等 |
| 生效范围 | **只对当前企业（租户）生效**，SaaS 模式下每个租户各自设置 | 平台专属，所有租户共用 |
| 谁可以修改 | 有「业务参数修改」权限的用户，包括各租户自己的管理员 | 只有平台租户的管理员 |

## 页面入口

系统管理 → 业务参数

![业务参数 - 供应链](/images/manual/system/biz-rule-scm.jpg)

参数按所属模块分页签显示，目前有「人力资源」「财务」「供应链」三个页签。每个参数下方是说明和默认值。

## 页面操作

- 修改过（与默认值不同并已保存）的参数显示蓝色「已修改」标签；
- 改动后尚未保存的参数显示橙色「未保存」标签；
- 当前值与默认值不同时，右侧出现「恢复默认」链接，点击后把输入恢复为默认值（仍需保存）；
- 页面占满内容区，参数较多时只有中间的参数区域滚动；页面底部固定显示「放弃修改」「保存（N）」按钮：「放弃修改」撤销全部未保存的改动，「保存（N）」一次保存全部改动（N 为改动的参数个数），各页签的改动会一起保存，成功后提示「已保存」；
- 保存后**立即生效**，不需要重新登录；
- 没有「业务参数修改」权限的用户只能查看，输入框不可编辑，也没有底部按钮。

保存时会校验取值，不符合时提示具体原因：

| 参数类型 | 校验 | 提示示例 |
| --- | --- | --- |
| 整数 | 必须是整数且在范围内 | 「「…」必须是整数」「「…」的范围是 0 - 100」 |
| 小数 | 必须是数字、在范围内，且不超过允许的小数位数（人力资源的参数最多 2 位小数）；保存时去掉末尾多余的 0（如 8.50 保存为 8.5） | 「「…」请填写数字」「「…」最多 2 位小数」 |
| 选项 | 必须是列出的选项之一 | 「「…」请从选项中选择」 |
| 表格（个税累计预扣率表） | 每个单元格按列的范围和小数位数校验；除允许留空的列外不能为空 | 「「…」第 N 行的「…」不能为空」「「…」第 N 行「…」的范围是 0 - 100」「「…」第 N 行「…」最多 2 位小数」 |

保存为默认值等同于恢复默认。

## 人力资源

![业务参数 - 人力资源](/images/manual/system/biz-rule-hr.jpg)

人力资源页签共 14 个参数，集中了工资、社保、考勤扣款、午休扣除、加班费、个税和试用期的计算规则。默认值与系统此前固定使用的规则相同，不修改时计算结果不变。修改后只影响**之后**的计算：已生成的工资表、已保存的员工档案、已有的考勤记录不会自动重算，需要时重新核算工资表；已有考勤记录的出勤时长可通过补卡重新计算。

[薪资档案](../hr/salary)页面的人工成本估算（月计薪天数、每日工时、默认社保比例）也读取本租户当前的参数值，人事人员只要有薪资档案的查看权限即可，不需要业务参数页面的权限。

| 参数 | 取值 | 默认值 | 说明（界面提示）与影响的业务 |
| --- | --- | --- | --- |
| 月计薪天数 | 1 ~ 31，最多 2 位小数 | 21.75 | 日工资 =（基本工资 + 岗位津贴）/ 月计薪天数。用于[工资表](../hr/payroll)的事假、病假、旷工扣款和加班费，以及[薪资档案](../hr/salary)的小时成本 |
| 每日工时（小时） | 1 ~ 24，最多 2 位小数 | 8 | 小时工资 = 日工资 / 每日工时；跨天的请假、加班每天按此计。请假审批流程的「天数」变量 = 小时数 ÷ 每日工时；[工时填报](../pm/timesheet)判断「全天请假」也按此 |
| 默认个人社保比例（%） | 0 ~ 100，最多 2 位小数 | 10.5 | 员工的薪资档案未选择社保方案时使用（养老 8% + 医疗 2% + 失业 0.5%），见[社保方案](../hr/social)；[薪资档案](../hr/salary)表单的「社保方案」提示和个人社保估算按当前值显示 |
| 默认单位社保比例（%） | 0 ~ 100，最多 2 位小数 | 26 | 员工的薪资档案未选择社保方案时使用（养老 16% + 医疗 8.5% + 失业 0.5% + 工伤 0.2% + 生育 0.8%）；薪资档案的月度人工成本、时薪成本按当前值估算 |
| 每次迟到 / 早退扣款（元） | 0 ~ 10000，最多 2 位小数 | 50 | 工资表的考勤扣款 = 迟到早退次数 × 每次扣款 + 旷工、事假、病假扣款 |
| 午休扣除阈值（小时） | 0 ~ 24，最多 2 位小数 | 5 | 上下班打卡间隔超过该小时数（不含等于）时，出勤时长扣除午休；修改后对之后打卡、补卡的记录生效。用于[考勤管理](../hr/attendance#考勤结果的计算)的出勤时长 |
| 午休时长（小时） | 0 ~ 24，最多 2 位小数 | 1 | 出勤时长 = 打卡间隔 − 午休时长（超过午休扣除阈值时），填 0 表示不扣午休；扣除后不会小于 0 |
| 病假扣发比例（%） | 0 ~ 100，最多 2 位小数 | 40 | 病假按小时工资的该比例扣发 |
| 工作日加班倍数 | 0 ~ 10，最多 2 位小数 | 1.5 | 加班费 = 加班小时 × 小时工资 × 倍数（转调休的加班不计） |
| 休息日加班倍数 | 0 ~ 10，最多 2 位小数 | 2 | 同上 |
| 法定节假日加班倍数 | 0 ~ 10，最多 2 位小数 | 3 | 同上 |
| 个税基本减除费用（元 / 月） | 0 ~ 1000000，最多 2 位小数 | 5000 | 本月应纳税所得额 = 应发 − 个人社保公积金 − 专项附加扣除 − 基本减除费用，见[专项附加扣除](../hr/deduction) |
| 个税累计预扣率表 | 表格，见下文 | 居民个人工资薪金累计预扣法的 7 档税率 | 按本年累计预扣预缴应纳税所得额：累计应纳税额 = 累计应纳税所得额 × 预扣率 − 速算扣除数；最后一档上限留空 |
| 默认试用期（月） | 整数 0 ~ 12 | 3 | 新建试用员工、候选人入职未填转正日期时，按入职日期加试用期计算计划转正日期，见[员工档案](../hr/employee)、[招聘管理](../hr/recruit) |

### 个税累计预扣率表

![个税累计预扣率表](/images/manual/system/biz-rule-tax.jpg)

表格有三列：「累计应纳税所得额上限（含）」「预扣率（%）」「速算扣除数」，每行一档。行末「插入行」在该行下方插入一档，「删除」删除该档（只剩一行时不能删除）。默认值为：

| 累计应纳税所得额上限（含） | 预扣率（%） | 速算扣除数 |
| --- | --- | --- |
| 36000 | 3 | 0 |
| 144000 | 10 | 2520 |
| 300000 | 20 | 16920 |
| 420000 | 25 | 31920 |
| 660000 | 30 | 52920 |
| 960000 | 35 | 85920 |
| 不限（留空） | 45 | 181920 |

规则：上限 0 ~ 1 亿、预扣率 0 ~ 100、速算扣除数 0 ~ 1 亿，都最多 2 位小数；除最后一档外都要填写上限且逐档递增，最后一档上限留空。不符合时提示「个税预扣率表除最后一档外都要填写上限，最后一档的上限留空（不限）」或「个税预扣率表第 N 档的上限必须大于上一档」。税法调整时在这里修改即可，不需要升级系统。

## 供应链

### 采购入库超收比例

| 项目 | 说明 |
| --- | --- |
| 名称 | 采购入库超收比例（%） |
| 取值 | 整数 0～100 |
| 默认值 | 0（不允许超收） |
| 影响的业务 | [采购入库](../scm/purchase-in)，包括由[送货通知](../scm/asn)收货、[寄售](../scm/consign)结算生成的采购入库单 |

采购入库数量可以超过订单未入库数量的比例。每一行订单明细允许的累计入库数量为：

> 订单数量 ×（1 + 超收比例）+ 补收数量

例如订单数量 100、超收比例 5%，累计最多可以入库 105。超出时保存提示「第 N 行（物料编码 物料名称）：数量超出允许超收 / 超发后的数量 X」，X 为本次最多还能入库的数量；比例为 0 时提示「数量超出未完成数量 X」。

::: tip 提示
- 新增采购入库时，表单只带出还有未完成数量的订单明细，「未完成数量」一列仍按订单数量计算；需要超收时，直接把「数量」改大即可。订单全部入库后状态变为已完成，不能再对它入库，因此超收要在最后一次入库时一并录入。
- 采购退货不受此参数影响，退货数量不能超过已入库的净数量。
:::

### 销售出库超发比例

| 项目 | 说明 |
| --- | --- |
| 名称 | 销售出库超发比例（%） |
| 取值 | 整数 0～100 |
| 默认值 | 0（不允许超发） |
| 影响的业务 | [销售出库](../scm/sales-out)，包括由[发货通知](../scm/delivery)出库、[寄售](../scm/consign)结算生成的销售出库单 |

销售出库数量可以超过订单未出库数量的比例，计算方式与采购入库超收比例相同：累计出库不超过 订单数量 ×（1 + 超发比例）+ 补发数量。超发的数量同样生成应收、扣减库存。销售退货不受此参数影响。

### 客户信用额度控制

| 项目 | 说明 |
| --- | --- |
| 名称 | 客户信用额度控制 |
| 取值 | 审核和出库时控制 / 只在出库时控制 / 不控制 |
| 默认值 | 审核和出库时控制 |
| 影响的业务 | [销售订单](../scm/sales)审核、[销售出库](../scm/sales-out) |

只对在[客户](../scm/customer#信用额度控制)资料中设置了信用额度的客户生效（没有设置额度的客户任何选项下都不控制）。

| 选项 | 审核销售订单时 | 销售出库时 |
| --- | --- | --- |
| 审核和出库时控制 | 应收余额 + 其他未完成订单 + 本单超过额度时，不能审核，提示「超出客户「…」的信用额度：…」 | 应收余额 + 未完成订单超过额度时，不能出库，提示「客户「…」超出信用额度，暂停出库：…」 |
| 只在出库时控制 | 不校验，可以正常审核 | 同上，超过额度时不能出库 |
| 不控制 | 不校验 | 不校验 |

「只在出库时控制」适合先接单、发货前再催款的企业：销售可以照常下单审核，仓库发货时再拦截。

## 财务

![业务参数 - 财务](/images/manual/system/biz-rule.jpg)

### 允许审核自己制单的凭证

| 项目 | 说明 |
| --- | --- |
| 名称 | 允许审核自己制单的凭证 |
| 取值 | 开启 / 关闭 |
| 默认值 | 关闭 |
| 影响的业务 | [凭证管理](../fin/voucher)的审核 |

关闭时遵循不相容职务分离：制单人不能审核自己的凭证，审核时提示「凭证 … 是你制单的，不能自己审核」（超级管理员除外）。财务人员较少、一人兼任制单和审核的企业可以开启。

::: warning 注意
开启后同一人可以完成凭证的制单和审核，内部控制减弱，请根据企业的管理要求和审计要求决定。已发布[凭证审批](../fin/voucher#凭证审批)流程时，凭证仍需提交审批。
:::

## 权限

| 操作 | 需要的权限 |
| --- | --- |
| 查看业务参数 | 「业务参数」菜单权限 |
| 修改业务参数 | 「业务参数修改」按钮权限 |

内置角色中，超级管理员拥有全部权限，普通用户（common）可以只读查看。SaaS 模式下，租户套餐中包含「业务参数」菜单时，租户管理员可以修改本租户的业务参数。

## 注意事项

::: tip 提示
- 业务参数只影响修改之后的操作，已经保存的单据不会重新校验。
- 新开通的租户使用默认值，需要时由租户管理员自行调整。
- 上线前建议与业务部门确认这些规则，见[首次上线的初始化步骤](./#首次上线的初始化步骤)。
:::
