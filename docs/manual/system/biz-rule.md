# 业务参数

业务参数集中管理各业务模块的控制规则，例如采购入库能否超收、销售出库能否超发、客户信用额度在哪些环节控制、出入库能否不选订单直接开单、销售出库能否从多个仓库出库、制单人能否审核自己的凭证、收付款是否先存草稿、完工入库是否按已领料校验，以及工资计算用的月计薪天数、每日工时、默认社保比例、考勤的午休扣除、加班倍数、个税预扣率表等人事计算规则，以及客户 RFM 分群的方式和阈值。企业可以按自己的管理要求调整，不需要修改系统。

## 与「参数设置」的区别

| | 业务参数（本页） | [参数设置](./config) |
| --- | --- | --- |
| 管什么 | 业务规则：超收超发、信用控制、直接开单、凭证审核、收付款草稿、完工入库领料校验、薪资考勤计算规则、客户分群参数等 | 系统级设置：系统名称、登录验证码、密码策略、会话、附件大小等 |
| 生效范围 | **只对当前企业（租户）生效**，SaaS 模式下每个租户各自设置 | 平台专属，所有租户共用 |
| 谁可以修改 | 有「业务参数修改」权限的用户，包括各租户自己的管理员 | 只有平台租户的管理员 |

## 页面入口

系统管理 → 业务参数

![业务参数 - 供应链](/images/manual/system/biz-rule-scm.jpg)

参数按所属模块分页签显示，目前有「人力资源」「财务」「供应链」「客户分析」「生产制造」五个页签。每个参数下方是说明和默认值。

## 页面操作

- 修改过（与默认值不同并已保存）的参数显示蓝色「已修改」标签；
- 改动后尚未保存的参数显示橙色「未保存」标签；
- 当前值与默认值不同时，右侧出现「恢复默认」链接，点击后把输入恢复为默认值（仍需保存）；
- 页面占满内容区，参数较多时只有中间的参数区域滚动；页面底部固定显示「放弃修改」「保存（N）」按钮：「放弃修改」撤销全部未保存的改动，「保存（N）」一次保存全部改动（N 为改动的参数个数），各页签的改动会一起保存，成功后提示「已保存」；
- 保存后**立即生效**，不需要重新登录；
- 没有「业务参数修改」权限的用户只能查看，输入框不可编辑，也没有底部按钮。

保存时会校验取值，不符合时提示具体原因：

| 参数类型 | 校验 | 提示示例 |
| --- | --- | --- |
| 整数 | 必须是整数且在范围内 | 「「…」必须是整数」「「…」的范围是 0 - 100」 |
| 小数 | 必须是数字、在范围内，且不超过允许的小数位数（人力资源的参数最多 2 位小数）；保存时去掉末尾多余的 0（如 8.50 保存为 8.5） | 「「…」请填写数字」「「…」最多 2 位小数」 |
| 选项 | 必须是列出的选项之一 | 「「…」请从选项中选择」 |
| 表格（个税累计预扣率表） | 每个单元格按列的范围和小数位数校验；除允许留空的列外不能为空 | 「「…」第 N 行的「…」不能为空」「「…」第 N 行「…」的范围是 0 - 100」「「…」第 N 行「…」最多 2 位小数」 |

保存为默认值等同于恢复默认。

## 人力资源

![业务参数 - 人力资源](/images/manual/system/biz-rule-hr.jpg)

人力资源页签共 16 个参数，集中了工资、社保（含入职 / 离职当月是否缴纳）、考勤扣款、午休扣除、加班费、个税和试用期的计算规则。默认值与系统此前固定使用的规则相同，不修改时计算结果不变。修改后只影响**之后**的计算：已生成的工资表、已保存的员工档案、已有的考勤记录不会自动重算，需要时重新核算工资表；已有考勤记录的出勤时长可通过补卡重新计算。

[薪资档案](../hr/salary)页面的人工成本估算（月计薪天数、每日工时、默认社保比例）也读取本租户当前的参数值，人事人员只要有薪资档案的查看权限即可，不需要业务参数页面的权限。

| 参数 | 取值 | 默认值 | 说明（界面提示）与影响的业务 |
| --- | --- | --- | --- |
| 月计薪天数 | 1 ~ 31，最多 2 位小数 | 21.75 | 日工资 =（基本工资 + 岗位津贴）/ 月计薪天数。用于[工资表](../hr/payroll)的事假、病假、旷工扣款和加班费，以及[薪资档案](../hr/salary)的小时成本 |
| 每日工时（小时） | 1 ~ 24，最多 2 位小数 | 8 | 小时工资 = 日工资 / 每日工时；跨天的请假、加班每天按此计。请假审批流程的「天数」变量 = 小时数 ÷ 每日工时；[工时填报](../pm/timesheet)判断「全天请假」也按此 |
| 默认个人社保比例（%） | 0 ~ 100，最多 2 位小数 | 10.5 | 员工的薪资档案未选择社保方案时使用（养老 8% + 医疗 2% + 失业 0.5%），见[社保方案](../hr/social)；[薪资档案](../hr/salary)表单的「社保方案」提示和个人社保估算按当前值显示 |
| 默认单位社保比例（%） | 0 ~ 100，最多 2 位小数 | 26 | 员工的薪资档案未选择社保方案时使用（养老 16% + 医疗 8.5% + 失业 0.5% + 工伤 0.2% + 生育 0.8%）；薪资档案的月度人工成本、时薪成本按当前值估算 |
| 入职当月缴社保的截止日 | 整数 0 ~ 31 | 15 | 入职日期在每月该日（含）之前的，入职当月缴纳社保公积金；之后入职的次月起缴。31 表示入职当月都缴纳，0 表示一律次月起缴。当月不缴时[工资表](../hr/payroll#社保公积金)中个人、单位社保和公积金都为 0 |
| 离职当月缴社保的起始日 | 整数 1 ~ 32 | 1 | 离职日期早于每月该日的，离职当月不再缴纳社保公积金；1 表示离职当月照常缴纳（次月停缴），32 表示离职当月一律不缴 |
| 每次迟到 / 早退扣款（元） | 0 ~ 10000，最多 2 位小数 | 50 | 工资表的考勤扣款 = 迟到早退次数 × 每次扣款 + 旷工、事假、病假扣款 |
| 午休扣除阈值（小时） | 0 ~ 24，最多 2 位小数 | 5 | 上下班打卡间隔超过该小时数（不含等于）时，出勤时长扣除午休；修改后对之后打卡、补卡的记录生效。用于[考勤管理](../hr/attendance#考勤结果的计算)的出勤时长 |
| 午休时长（小时） | 0 ~ 24，最多 2 位小数 | 1 | 出勤时长 = 打卡间隔 − 午休时长（超过午休扣除阈值时），填 0 表示不扣午休；扣除后不会小于 0。判断[请假当天的迟到早退](../hr/attendance#考勤结果的计算)时也留出这段午休 |
| 病假扣发比例（%） | 0 ~ 100，最多 2 位小数 | 40 | 病假按小时工资的该比例扣发 |
| 工作日加班倍数 | 0 ~ 10，最多 2 位小数 | 1.5 | 加班费 = 加班小时 × 小时工资 × 倍数（转调休的加班不计） |
| 休息日加班倍数 | 0 ~ 10，最多 2 位小数 | 2 | 同上 |
| 法定节假日加班倍数 | 0 ~ 10，最多 2 位小数 | 3 | 同上 |
| 个税基本减除费用（元 / 月） | 0 ~ 1000000，最多 2 位小数 | 5000 | 本月应纳税所得额 = 应发 − 个人社保公积金 − 专项附加扣除 − 基本减除费用，见[专项附加扣除](../hr/deduction) |
| 个税累计预扣率表 | 表格，见下文 | 居民个人工资薪金累计预扣法的 7 档税率 | 按本年累计预扣预缴应纳税所得额：累计应纳税额 = 累计应纳税所得额 × 预扣率 − 速算扣除数；最后一档上限留空 |
| 默认试用期（月） | 整数 0 ~ 12 | 3 | 新建试用员工、候选人入职未填转正日期时，按入职日期加试用期计算计划转正日期，见[员工档案](../hr/employee)、[招聘管理](../hr/recruit) |

### 个税累计预扣率表

![个税累计预扣率表](/images/manual/system/biz-rule-tax.jpg)

表格有三列：「累计应纳税所得额上限（含）」「预扣率（%）」「速算扣除数」，每行一档。行末「插入行」在该行下方插入一档，「删除」删除该档（只剩一行时不能删除）。默认值为：

| 累计应纳税所得额上限（含） | 预扣率（%） | 速算扣除数 |
| --- | --- | --- |
| 36000 | 3 | 0 |
| 144000 | 10 | 2520 |
| 300000 | 20 | 16920 |
| 420000 | 25 | 31920 |
| 660000 | 30 | 52920 |
| 960000 | 35 | 85920 |
| 不限（留空） | 45 | 181920 |

规则：上限 0 ~ 1 亿、预扣率 0 ~ 100、速算扣除数 0 ~ 1 亿，都最多 2 位小数；除最后一档外都要填写上限且逐档递增，最后一档上限留空。不符合时提示「个税预扣率表除最后一档外都要填写上限，最后一档的上限留空（不限）」或「个税预扣率表第 N 档的上限必须大于上一档」。税法调整时在这里修改即可，不需要升级系统。

## 供应链

### 采购入库超收比例

| 项目 | 说明 |
| --- | --- |
| 名称 | 采购入库超收比例（%） |
| 取值 | 整数 0～100 |
| 默认值 | 0（不允许超收） |
| 影响的业务 | [采购入库](../scm/purchase-in)，包括由[送货通知](../scm/asn)收货、[寄售](../scm/consign)结算生成的采购入库单 |

采购入库数量可以超过订单未入库数量的比例。每一行订单明细允许的累计入库数量为：

> 订单数量 ×（1 + 超收比例）+ 补收数量

例如订单数量 100、超收比例 5%，累计最多可以入库 105。超出时保存提示「第 N 行（物料编码 物料名称）：数量超出允许超收 / 超发后的数量 X」，X 为本次最多还能入库的数量；比例为 0 时提示「数量超出未完成数量 X」。

::: tip 提示
- 新增采购入库时，表单只带出还有未完成数量的订单明细，「未完成数量」一列仍按订单数量计算；需要超收时，直接把「数量」改大即可。订单全部入库后状态变为已完成，不能再对它入库，因此超收要在最后一次入库时一并录入。
- 采购退货不受此参数影响，退货数量不能超过已入库的净数量。
:::

### 销售出库超发比例

| 项目 | 说明 |
| --- | --- |
| 名称 | 销售出库超发比例（%） |
| 取值 | 整数 0～100 |
| 默认值 | 0（不允许超发） |
| 影响的业务 | [销售出库](../scm/sales-out)，包括由[发货通知](../scm/delivery)出库、[寄售](../scm/consign)结算生成的销售出库单 |

销售出库数量可以超过订单未出库数量的比例，计算方式与采购入库超收比例相同：累计出库不超过 订单数量 ×（1 + 超发比例）+ 补发数量。超发的数量同样生成应收、扣减库存。销售退货不受此参数影响。

### 客户信用额度控制

| 项目 | 说明 |
| --- | --- |
| 名称 | 客户信用额度控制 |
| 取值 | 审核和出库时控制 / 只在出库时控制 / 不控制 |
| 默认值 | 审核和出库时控制 |
| 影响的业务 | [销售订单](../scm/sales)审核、[销售出库](../scm/sales-out) |

只对在[客户](../scm/customer#信用额度控制)资料中设置了信用额度的客户生效（没有设置额度的客户任何选项下都不控制）。

| 选项 | 审核销售订单时 | 销售出库时 |
| --- | --- | --- |
| 审核和出库时控制 | 应收余额 + 其他未完成订单 + 本单超过额度时，不能审核，提示「超出客户「…」的信用额度：…」 | 应收余额 + 未完成订单超过额度时，不能出库，提示「客户「…」超出信用额度，暂停出库：…」 |
| 只在出库时控制 | 不校验，可以正常审核 | 同上，超过额度时不能出库 |
| 不控制 | 不校验 | 不校验 |

「只在出库时控制」适合先接单、发货前再催款的企业：销售可以照常下单审核，仓库发货时再拦截。

销售出库[直接开单](../scm/sales-out#直接开单)时，系统生成订单并审核、再出库，两个环节都按本参数校验。

### 允许直接开单

| 项目 | 说明 |
| --- | --- |
| 名称 | 允许直接开单 |
| 取值 | 开启 / 关闭 |
| 默认值 | 开启 |
| 影响的业务 | [销售出库、销售退货](../scm/sales-out#直接开单)，[采购入库、采购退货](../scm/purchase-in#直接开单) |

界面说明：「销售出库、采购入库及退货可以不选订单，直接选择往来单位和商品开单，系统自动生成已审核的订单（来源「直接开单」）；关闭后必须引用订单」。

- 开启时，新增出入库单默认为直接开单，也可以引用订单（退货引用原出入库单）；
- 关闭后，表单中必须引用订单，提示「业务参数未开启直接开单，需引用订单」；不引用就保存时提示「…必须引用订单（业务参数未开启「允许直接开单」）」；
- 关闭不影响已经直接开单生成的订单和单据。

希望所有出入库都必须先有经过审核的订单（例如严格执行采购、销售审批）的企业，可以关闭此参数。

### 销售出库明细可选仓库

| 项目 | 说明 |
| --- | --- |
| 名称 | 销售出库明细可选仓库 |
| 取值 | 开启 / 关闭 |
| 默认值 | 开启 |
| 影响的业务 | [销售出库](../scm/sales-out#明细选择仓库)（包括直接开单和引用订单） |

界面说明：「销售出库的每行明细可以从不同的仓库出库（默认取表头仓库）」。开启时销售出库的明细多一列「仓库」，为空的行从表头仓库出库；关闭后整张单据从表头仓库出库。已经保存的多仓库出库单不受影响。

修改这两个参数后，其他已登录的用户刷新浏览器页面后表单才按新设置显示；保存单据时始终按当前的参数校验。

## 财务

![业务参数 - 财务](/images/manual/system/biz-rule.jpg)

### 允许审核自己制单的凭证

| 项目 | 说明 |
| --- | --- |
| 名称 | 允许审核自己制单的凭证 |
| 取值 | 开启 / 关闭 |
| 默认值 | 关闭 |
| 影响的业务 | [凭证管理](../fin/voucher)的审核 |

关闭时遵循不相容职务分离：制单人不能审核自己的凭证，审核时提示「凭证 … 是你制单的，不能自己审核」（超级管理员除外）。财务人员较少、一人兼任制单和审核的企业可以开启。

::: warning 注意
开启后同一人可以完成凭证的制单和审核，内部控制减弱，请根据企业的管理要求和审计要求决定。已发布[凭证审批](../fin/voucher#凭证审批)流程时，凭证仍需提交审批。
:::

### 冲账单复核人不能是制单人

| 项目 | 说明 |
| --- | --- |
| 名称 | 冲账单复核人不能是制单人 |
| 取值 | 开启 / 关闭 |
| 默认值 | 关闭 |
| 影响的业务 | [冲账单](../fin/offset)的复核 |

界面说明：「开启后制单人不能复核自己录入的冲账单，适合制单与复核分开的公司；一个人操作的小公司保持关闭即可」。开启后制单人复核自己的冲账单时提示「冲账单 … 由你制单，复核人不能是制单人」。

### 收付款先存草稿

| 项目 | 说明 |
| --- | --- |
| 名称 | 收付款先存草稿 |
| 取值 | 开启 / 关闭 |
| 默认值 | 关闭 |
| 影响的业务 | [收款单、付款单](../fin/settlement#草稿与确认)的新增和修改 |

界面说明：「开启后新建的收款单、付款单先保存为草稿，可修改、删除，确认后才核销单据、冲抵预收预付、多收转预收预付（付款发布了审批流程时，确认即提交审批，审批通过后核销）；关闭时保存即生效」。

- **关闭**（默认）：与以前一样，收付款单保存即生效、立即核销；
- **开启**：收付款录入页的按钮变为「**保存草稿**」和「**保存并确认收款**」（付款为「保存并确认付款」）；草稿不核销任何单据，确认后才生效。确认需要「收款单确认」「付款单确认」按钮权限，适合出纳录入、会计确认的分工。

修改后，其他已登录的用户刷新浏览器页面后录入页才按新设置显示按钮。已经保存的草稿不受关闭参数影响，仍可在列表中「确认」。

## 生产制造

![业务参数 - 生产制造](/images/manual/system/biz-rule-mes.jpg)

### 完工入库领料校验

| 项目 | 说明 |
| --- | --- |
| 名称 | 完工入库领料校验 |
| 取值 | 不校验 / 提示 / 禁止 |
| 默认值 | 提示 |
| 影响的业务 | [生产工单](../mes/wo#完工入库领料校验)的完工入库 |

界面说明：「累计完工入库数量超过按已领料（领料 + 补料 − 退料）计算的齐套数量时的处理：不校验；提示（确认后仍可入库）；禁止。齐套数量 = 各用料的净领料 ÷ 单位用量（含损耗）的最小值，替代料与主料合并计算」。

| 选项 | 完工入库时 |
| --- | --- |
| 不校验 | 不计算可完工数量，与以前一致 |
| 提示 | 页面显示按已领料可完工的数量；超出时弹出确认框，确认后仍可入库 |
| 禁止 | 超出按已领料可完工的数量时不能入库，提示「按已领料只够完工 …（已完工 …，受物料「…」限制），请先领料或补料」 |

默认「提示」不会拦截先入库、后补领料的现有做法；需要严格按领料控制完工时改为「禁止」。

## 客户分析

「客户分析」页签设置客户 RFM 分群的默认方式和阈值，供应链「进销存报表」的[客户分析（RFM）](../scm/jxc-rfm#分群参数)和客户关系的[客户分析](../crm/analysis#rfm-客户分层规则)都使用。两个页面上可以临时修改参数，有「业务参数修改」权限的用户也可以在页面上点「保存为默认」直接写入这里。

| 参数 | 取值 | 默认值 | 说明（界面提示） |
| --- | --- | --- | --- |
| RFM 分群方式 | 固定阈值 / 平均分 | 固定阈值 | 固定阈值按下面三个参数判断高低；平均分按 R、F、M 的五分位得分与全体平均分比较（随客户整体水平自动调整）。查询页面可以临时修改 |
| R 最近订货（天之内） | 整数 1 ~ 3650 | 30 | 固定阈值方式下，最近一次订货在多少天之内算「最近订过货」（R 高） |
| F 订货频率（次 / 月） | 0 ~ 1000，最多 2 位小数 | 1 | 固定阈值方式下，每月订货次数（统计期间的订货单数 ÷ 月数）不少于多少次算「经常订货」（F 高） |
| M 平均订货金额（元 / 次） | 0 ~ 1 亿，最多 2 位小数 | 1000 | 固定阈值方式下，平均每次订货金额（净销售额 ÷ 订货单数）不少于多少元算「金额高」（M 高） |

在查询页面临时修改时同样校验范围，超出时提示「最近订货天数须在 1–3650 之间」「订货频率须在 0–1000 之间，最多两位小数」「平均订货金额须在 0–100000000 之间，最多两位小数」。

## 权限

| 操作 | 需要的权限 |
| --- | --- |
| 查看业务参数 | 「业务参数」菜单权限 |
| 修改业务参数 | 「业务参数修改」按钮权限 |

内置角色中，超级管理员拥有全部权限，普通用户（common）可以只读查看。SaaS 模式下，租户套餐中包含「业务参数」菜单时，租户管理员可以修改本租户的业务参数。

## 注意事项

::: tip 提示
- 业务参数只影响修改之后的操作，已经保存的单据不会重新校验。
- 新开通的租户使用默认值，需要时由租户管理员自行调整。
- 上线前建议与业务部门确认这些规则，见[首次上线的初始化步骤](./#首次上线的初始化步骤)。
:::
