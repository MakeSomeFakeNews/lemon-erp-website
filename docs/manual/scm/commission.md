# 销售提成

销售提成按**销售订单的业务员**统计每月业绩（销售额、毛利、回款），按预先设置的提成规则（支持按物料分类、按业务员、阶梯门槛）计算每个业务员的提成，可以手工调整，确认后在生成当月[工资表](../hr/payroll)时计入「销售提成」。

## 页面入口

供应链 → 销售 → 销售提成

页面分为「提成表」「提成规则」两个页签。

## 业务员

每张销售订单都有一个**业务员**，提成就按业务员归集：

- 新建销售订单时，业务员默认取[客户](./customer)的「负责销售」，客户没有设置负责销售时为制单人；
- 订单详情的「业务员」后面有「修改」链接（需要销售订单修改权限），可以随时改为其他用户，包括已审核、已完成的订单。修改只影响之后计算（或重新计算）的提成，已确认的提成表不变。

详见[销售订单](./sales#业务员)。

## 提成规则

点「提成规则」页签：

![提成规则](/images/manual/scm/commission-rule.jpg)

页签提示：「同一业务员、物料分类、依据取最具体（指定业务员 → 指定分类 → 通用）且门槛最高的已达成规则；不同依据的提成相加」。

**列表列**：规则名称、依据（销售额 / 毛利 / 回款）、业务员（为空显示「全部业务员」）、物料分类（为空显示「全部」）、业绩门槛（为 0 显示「-」，否则显示「≥ 金额」）、比例、状态、备注、操作（「编辑」「删除」）。

点「新增规则」：

![新增提成规则](/images/manual/scm/commission-rule-form.jpg)

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 规则名称 | 是 | 最多 64 字，如「销售额基础提成」 |
| 提成依据 | 是 | 销售额 / 毛利 / 回款，默认销售额 |
| 业务员 | 否 | 为空适用全部业务员 |
| 物料分类 | 否 | 为空适用全部分类；依据为「回款」时不可选（回款不区分物料分类） |
| 业绩门槛 | 否 | 默认 0。业务员当月该依据的业绩**合计**达到这个金额时才适用，用于阶梯提成 |
| 提成比例 | 是 | 0 ~ 100%，最多 3 位小数 |
| 状态 | 否 | 默认启用；停用的规则不参与计算 |
| 备注 | 否 | |

维护规则需要「提成规则维护」权限。

### 规则怎么匹配

计算时，对每个业务员、每种依据、每个物料分类（回款不分分类）分别找一条规则：

1. 只看已启用、依据相同、业务员为空或就是该业务员、物料分类为空或就是该分类的规则；
2. 业绩门槛不超过该业务员当月**该依据的业绩合计**（不分分类）；
3. 满足条件的规则中取最具体的：指定了业务员的优先，其次指定了物料分类的，最后是通用规则；同样具体时取门槛最高的一条；
4. 提成 = 该分类的业绩 × 规则比例；
5. 不同依据的提成相加。例如同时设置了按销售额和按回款的规则，两部分提成都会计入。

**示例**（阶梯提成）：

| 规则名称 | 依据 | 业务员 | 物料分类 | 业绩门槛 | 比例 |
| --- | --- | --- | --- | --- | --- |
| 销售额基础提成 | 销售额 | 全部 | 全部 | 0 | 2% |
| 销售额超 50 万 | 销售额 | 全部 | 全部 | 500,000 | 3% |
| 成品加提 | 销售额 | 全部 | 成品 | 0 | 4% |

业务员当月销售额 60 万（其中成品 20 万、原材料 40 万）：成品部分匹配「成品加提」（指定分类更具体），提成 20 万 × 4% = 8,000；原材料部分门槛已达到 50 万，匹配「销售额超 50 万」，提成 40 万 × 3% = 12,000；合计 20,000。

## 提成表

![销售提成表](/images/manual/scm/commission-sheet.jpg)

顶部选择**期间**（月份，默认本月），右侧显示提成表的状态（草稿 / 已确认）和「提成合计」。还没有计算的期间，表格提示「本期还没有计算提成」。

页签提示：「按销售订单的业务员统计当月业绩：销售额为销售出库的不含税金额（扣除退货），毛利 = 销售额 - 出库数量 × 当期成本单价（未核算时取参考成本价），回款为收款核销的销售应收。重新计算时保留手工调整。」

**列表列**：

| 列 | 说明 |
| --- | --- |
| 业务员 | — |
| 销售额 | 当月[销售出库](./sales-out)的不含税金额，减去当月销售退货 |
| 毛利 | 销售额 − 出库数量 × 当期成本单价。当月还没有做[成本核算](../fin/cost)时，成本单价取物料的参考成本价 |
| 回款 | 当月已生效的收款单核销到销售出库 / 退货应收单的金额 |
| 规则提成 | 按提成规则计算的金额 |
| 调整 | 手工调整金额 |
| 应发提成 | 规则提成 + 调整，加粗显示 |
| 调整原因 | — |
| 操作 | 草稿时显示「调整」 |

负数金额显示为红色（如退货多于出库）。点每行左侧的展开按钮查看计算明细：依据、物料分类、业绩、匹配的规则、比例、提成。列表按应发提成从高到低排列。

各项业绩都按单据日期归属：销售额按出库 / 退货单的业务日期，回款按收款单的结算日期。只统计设置了业务员的销售订单。

### 操作

| 按钮 | 显示条件 | 作用 |
| --- | --- | --- |
| 计算提成 | 该期间还没有提成表 | 按当前规则和业绩生成草稿提成表，每个有业绩的业务员一行 |
| 重新计算 | 草稿 | 按最新的业绩和规则重新计算，**保留**各业务员已填写的调整金额和调整原因 |
| 调整 | 草稿，行操作 | 填写「调整金额」（正数增加、负数扣减，应发提成 = 规则计算的提成 + 调整）和「调整原因」 |
| 确认 | 草稿 | 提示「确认提成表？确认后生成的工资表计入销售提成。」确认后不能再计算、调整 |
| 取消确认 | 已确认 | 提示「取消确认？已生成的工资表不会自动更新，需重新生成草稿工资表。」回到草稿 |

计算、调整、确认、取消确认需要「提成计算与确认」权限。

### 操作步骤

1. 月初在「提成规则」中维护好规则（只需维护一次，规则变化时再调整）；
2. 月末销售出库、收款核销都录入完成后（需要按毛利提成的，建议先做当月[成本核算](../fin/cost)），在「提成表」中选择期间，点「计算提成」；
3. 展开各业务员核对计算明细，有特殊情况的点「调整」；
4. 点「确认」；
5. 人事在[薪酬核算](../hr/payroll)中生成（或重新生成）当月工资表，已确认的应发提成计入员工的「销售提成」。

## 与其他模块的联动

- **销售订单**：业务员在订单上记录和修改，见[销售订单](./sales#业务员)；
- **销售出库 / 退货、收款核销**：提供销售额、毛利和回款业绩；
- **成本核算**：毛利按当期成本单价计算；
- **薪酬核算**：工资表生成时读取当月**已确认**的提成表，按员工档案关联的登录账号把应发提成计入「销售提成」，并计入应发工资。业务员没有关联员工档案，或员工没有建立薪资档案的，提成不会进入工资表。

## 注意事项

::: warning 注意
- 每个期间只有一张提成表；
- 提成表确认后再取消确认、修改，已经生成的工资表不会自动更新，需要在[薪酬核算](../hr/payroll)中对草稿工资表「重新计算」；工资表已确认的需要先取消确认；
- 没有设置任何规则时也可以计算，各业务员只显示业绩，规则提成为 0，可通过「调整」手工录入提成。
:::
