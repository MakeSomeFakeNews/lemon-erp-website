# 定时任务

定时任务是系统按固定时间自动执行的后台工作，例如每天早上发送跟进提醒、到期提醒，凌晨同步数据仓库、让调薪和工程变更按生效日期生效。管理员可以在这里调整执行时间和参数、启用或停用任务、立即执行一次，并查看执行日志。

::: warning 平台专属
定时任务是平台专属功能，SaaS 模式下只有平台租户的管理员可以使用。任务对所有租户统一调度：每次执行时按租户逐个运行（只运行启用且未到期的租户），某个租户失败不影响其他租户，执行说明中汇总各租户的结果。
:::

## 页面入口

系统监控 → 定时任务

![定时任务](/images/manual/monitor/job.jpg)

## 列表字段

| 列 | 说明 |
| --- | --- |
| 任务名称 | 如「客户跟进提醒」 |
| 任务标识 | 任务的唯一编码，如 `crm.followRemind` |
| Cron | 执行时间表达式 |
| 参数 | 任务参数，如 `days=30` |
| 状态 | 启用 / 停用 |
| 最近执行 | 最近一次执行的开始时间 |
| 结果 | 最近一次执行成功 / 失败 |
| 执行说明 | 最近一次执行的结果说明，如「提醒 3 个客户」「没有逾期应收」，多租户时按租户列出 |
| 操作 | 「执行」「修改」「日志」 |

## 内置任务

系统共内置以下 17 个任务，提醒类任务把消息发送到相关人员的站内消息（顶栏铃铛）中，并对同一对象做了去重，不会重复打扰：

| 任务名称 | 任务标识 | 默认执行时间 | 默认参数 | 作用 |
| --- | --- | --- | --- | --- |
| 经营预警推送 | bi.alertNotify | 每天 09:00 | | 评估全部启用的预警规则，把触发的预警推送给有决策支持权限的用户（每条规则每天一次） |
| 数据仓库同步 | bi.etl | 每天 01:30 | | 把销售、采购、库存、生产、财务数据同步到数据仓库，供[商务智能](../bi/)分析使用 |
| 合同回款提醒 | crm.collectionRemind | 每天 08:50 | | 执行中合同的逾期回款计划，提醒合同负责人（每期一次） |
| 客户跟进提醒 | crm.followRemind | 每天 08:00 | | 下次跟进时间在今天及之前的客户，提醒负责人（每个客户每天一次） |
| 客户公海回收 | crm.poolReclaim | 每天 02:30 | days=30 | 负责人超过 days 天没有跟进的未成交客户退回公海，并通知原负责人 |
| 应收逾期提醒 | fin.arOverdue | 每天 09:00 | | 汇总逾期未收的应收单，提醒应收人员 |
| 票据到期提醒 | fin.noteDue | 每天 09:10 | days=7 | days 天内到期仍未处理的票据：应收票据提醒托收，应付票据提醒备足资金兑付，通知票据管理人员 |
| 劳动合同到期提醒 | hr.contractExpiry | 每天 08:40 | days=30 | 到期日已过的合同改为「已到期」；days 天内到期的合同提醒人事（每份合同一次） |
| 试用期到期提醒 | hr.probationRemind | 每天 08:10 | days=15 | days 天内试用期到期的员工，提醒人事和所在部门负责人（每人一次） |
| 调薪生效 | hr.salaryApply | 每天 00:05 | | 把今天生效的调薪同步到薪资档案 |
| 工程变更生效 | mes.ecnEffect | 每天 00:05 | | 已批准且到了生效日期的工程变更，切换 BOM 版本 |
| 设备保养提醒 | mes.maintainRemind | 每天 08:30 | days=3 | days 天内到期的设备保养，提醒设备维护人员（每台设备每个保养日期一次） |
| 工单逾期提醒 | mes.woOverdue | 每天 08:40 | | 已过计划完工日期仍未完工的工单，提醒制单人（每张工单每天一次） |
| 项目任务逾期提醒 | pm.taskOverdue | 每天 08:50 | | 进行中项目里已过计划完成日期的任务，提醒任务负责人（每个任务每天一次） |
| 纠正预防逾期提醒 | qms.capaOverdue | 每天 09:20 | | 超过要求完成日期仍未关闭的纠正预防（8D），通知负责人 |
| 补货提醒 | scm.reorder | 每天 08:30 | | 预计库存不高于再订货点的物料，每天提醒采购人员一次 |
| 批次临期提醒 | wms.batchExpiry | 每天 08:20 | days=30 | days 天内到期且有库存的批次，提醒仓库人员（每个批次一次） |

## 修改任务

点击「修改」打开「修改定时任务」：

![修改定时任务](/images/manual/monitor/job-edit.jpg)

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 任务 | | 显示任务名称和标识，不可修改 |
| Cron 表达式 | 是 | 6 段：秒 分 时 日 月 周，如 `0 30 1 * * *` 表示每天 01:30；格式错误时提示「Cron 表达式不正确」 |
| 参数 | 否 | `key=value` 格式，多个用英文逗号分隔，如 `days=30` |
| 状态 | 是 | 启用 / 停用。停用后不再自动执行，但仍可手动「执行」 |
| 备注 | 否 | |

保存后立即按新的时间重新调度，无需重启系统。

## Cron 表达式写法

柠檬ERP 使用 6 段 Cron 表达式，各段依次为：

| 段 | 秒 | 分 | 时 | 日 | 月 | 周 |
| --- | --- | --- | --- | --- | --- | --- |
| 取值 | 0-59 | 0-59 | 0-23 | 1-31 | 1-12 | 0-7（0 和 7 都是周日）或 MON-SUN |

常用符号：`*` 表示每一个；`,` 列举多个值；`-` 表示范围；`/` 表示间隔；`?` 用在日或周上表示不指定。

| 表达式 | 含义 |
| --- | --- |
| `0 0 8 * * *` | 每天 08:00 |
| `0 30 1 * * *` | 每天 01:30 |
| `0 0 9 * * MON-FRI` | 工作日（周一至周五）09:00 |
| `0 0 8,14 * * *` | 每天 08:00 和 14:00 |
| `0 0 */2 * * *` | 每 2 小时整点 |
| `0 */30 * * * *` | 每 30 分钟 |
| `0 0 2 1 * *` | 每月 1 日 02:00 |

::: tip 提示
执行时间以服务器时区为准。数据仓库同步等耗时任务建议放在夜间；多个提醒任务可以错开几分钟，避免同时运行。
:::

## 立即执行

点击「执行」，任务会马上运行一次（不影响原有的定时计划），完成后提示执行结果（成功时显示执行说明，失败时显示错误原因），并刷新列表。

- 同一任务正在运行时不能重复执行，提示「任务『xxx』正在运行」；
- 手动执行在执行日志中记为「手动」触发；
- 常用于验证修改后的参数、补发当天遗漏的提醒，或在导入数据后立即同步数据仓库。

## 执行日志

- 行内「日志」：查看该任务的执行日志；
- 工具栏「执行日志」：查看全部任务的执行日志。

![执行日志](/images/manual/monitor/job-log.jpg)

| 列 | 说明 |
| --- | --- |
| 任务 | 任务标识 |
| 触发 | 定时 / 手动 |
| 开始时间 | |
| 耗时(ms) | 执行用时，毫秒 |
| 结果 | 成功 / 失败 |
| 说明 | 执行说明或失败原因；多租户时按「租户名：结果」用分号分隔 |

## 注意事项

::: warning 注意
- 部署时如果在服务端关闭了定时任务调度（一般只在测试环境这样做），所有任务都不会自动执行，只能在本页手动执行。
- 停用提醒类任务后，相关人员将收不到对应的站内提醒，首页待办中的数据不受影响。
- 新版本增加的任务会在系统启动时自动登记，使用默认的执行时间和参数。
:::
